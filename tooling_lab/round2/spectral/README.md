# FFT spectral transport and exact large-witness replay

This round implements the scaling backend proposed in round 1. It replaces dense matrices with FFT multiplication, keeps the positive and negative spectral directions separate, completes missing symmetry partners, and optimizes one vector against several fixed translations. An independent integer-convolution backend checks the resulting Rayleigh witnesses without constructing the dense matrix.

The output consists of **finite lower witnesses and arithmetic diagnostics**. Numerical Ritz values and residuals do not certify a global spectral upper bound. No Paley conjecture or Proximity Prize proof is attempted or claimed. The standard FFT, Lanczos, symmetry reduction and NTT methods are credited below; external novelty of this application remains unestablished.

## Exact operator represented by the FFT

For prime p congruent to 1 modulo 4, let

```
C = {x : chi(x)=chi(x-1)=1}, m=(p-5)/4
H = S_C/sqrt(p) - J_C/p.
```

This is the same `H=2B-I` used in round 1. The quadratic Gauss sum identity diagonalizes the ambient operator `S/sqrt(p)` in the additive Fourier basis, with eigenvalue `chi(k)` at frequency k, including zero eigenvalue at k=0. Thus a product by H is:

1. Extend v by zero from C to F_p.
2. Apply a real FFT, multiply frequency k by chi(k), and inverse FFT.
3. Restrict to C and subtract `sum(v)/p` at each coordinate.

No matrix entries are approximated by a low-rank kernel. The mathematical operator is exact; its FFT evaluation uses floating point. The character array is constructed by enumerating nonzero squares, avoiding p modular exponentiations. Dense allocation is explicitly guarded at p>4001.

[fft_transport.py](fft_transport.py) compares this product against the independently constructed dense character matrix at p=101,401,1009,4001. The observed maximum entrywise matvec error is saved for each case. It also compares computed Ritz values with the dense spectrum and verifies the selected extremal values there. At larger inputs it computes fresh residuals `||Hv-lambda v||`; these indicate proximity to some eigenvalue of the symmetric matrix, but do not exclude an unobserved more extreme eigenvalue.

## Revision forced by the first dense comparison

A single-start Lanczos calculation can miss partners in an exactly repeated eigenspace. At p=401, the first positive k=4 run returned approximately

```
0.80086607, 0.79253676, 0.74626376, 0.74006116
```

while the dense top four, counted with multiplicity, include `0.80086607` twice. The original ordered comparison correctly failed. Increasing confidence in the convergence flag would not repair that omission.

The revision uses the already established S3 action on C, generated by `x -> 1-x` and `x -> 1/x`. Both permutations commute with H: reflection uses `chi(-1)=1`, and inversion changes `chi(x-y)` by `chi(xy)=1` on C. All six images of the computed Ritz vectors are adjoined, numerical dependencies are discarded by a thin Gram decomposition, and a new Rayleigh–Ritz compression is computed. Directions below the original one-sided compressed floor (up to a numerical allowance 1e-6) are discarded. This recovered both top partners at p=401 and produced a six-dimensional positive span.

This action and its representation theory were already proved in pass 25. The new work is its use as a computational completion rule after an observed Lanczos multiplicity failure. It does not recover every spectral direction: an entire missing eigenspace or multiplicity copy can remain absent. The output is therefore called a **computed one-sided Ritz span**, never a complete spectral tail.

## Several translations, one constrained vector

Within each positive or negative computed span U, the first Ritz vector supplies four nonzero shifts with the largest absolute autocorrelations. Opposite shifts are identified, so t and -t are not counted twice. Their signs are fixed once. The objective is

```
K = (1/4) sum_t sign_t * sym(U^T tau_t U)
maximize alpha^T K alpha, ||alpha||=1
v = U alpha.
```

This is one vector maximizing the average of four overlaps. It does not optimize a different vector for each shift. Using only one spectral sign avoids round 1's cancellation between positive and negative Rayleigh quotients. The actual quotient of the final vector is recomputed, and checked against the minimum and maximum eigenvalues of `U^T (sign*H) U`.

This subspace restriction is an implementable substitute for a global Rayleigh-constrained optimization problem. It guarantees the compressed Rayleigh constraint in exact arithmetic, while searching only the supplied span. It cannot prove that the span contains the best arithmetically structured dangerous direction.

Four further shifts selected from the same seed, but excluded from the objective, provide a held-out-shift diagnostic. They are not independent held-out data, because all eight came from the same seed. The tool also measures a uniformly sampled four-shift objective and repeats adaptive shift selection after a coordinate permutation of the span. The latter is a same-spectrum graph relabelling control. There is one fixed-seed control per case, not a statistical significance test.

The main logs retain raw and completed runs. Their shifts can differ when the first Ritz vector rotates inside a degenerate eigenspace, so differences between those two scalar scores are **not** automatically completion gains. [completion_audit.py](completion_audit.py) explicitly holds the shifts and signs fixed before and after completion. In that audit p=401's positive objective increases by 0.027103. Other effects range from nearly zero to 0.014782 at p=101 negative. Numerical subspace-containment error is recorded; the tiny negative gain at p=1009 positive is within that error. None is evidence of a new asymptotic estimate.

## Exact integer witness certification

The discovered vector is rounded to integer coefficients with maximum magnitude 1024, serialized together with every vertex of C, and hashed. Floating-point search proposes a strict rational lower bound for its directional Rayleigh quotient. [exact_ntt.cpp](exact_ntt.cpp) then recomputes the signed quadratic form using a number theoretic transform modulo 998244353.

Let `z` be the integer vector extended by zero and let `L=||z||_1`. Cyclic character convolution satisfies

```
c(x) = sum_y chi(x-y) z(y),  |c(x)| <= L.
```

The program zero-pads to an NTT length at least `2p-1`, multiplies the two polynomials modulo the NTT prime, and folds degrees modulo `X^p-1`. It checks `2L < 998244353`, so the centered residue uniquely determines every signed integer c(x). Then

```
A = sum_x z(x)c(x)
n = sum_x z(x)^2
s = sum_x z(x)
Rayleigh(H,z) = A/(sqrt(p)n) - s^2/(pn).
```

The input prime, complete neighborhood, coefficient range, transform length, modular prime and primitive-root conditions are checked. At p<=4001 every recovered row convolution is also checked by direct integer summation. All integer products fit int64 under the checked L bound. Python integers handle the larger certificate comparisons.

To check `sign*Rayleigh > a/b`, [verify_exact.py](verify_exact.py) tests

```
b*sign*A*sqrt(p) > a*p*n + b*sign*s^2
```

by integer squaring **after separating signs**. Floating-point values only propose a/b; no floating-point tolerance accepts the strict inequality. These are exact finite lower certificates, independent of the accuracy or completeness of the eigensolver.

## A larger exact failure of the pointwise transport hypothesis

At p=65537, a second rounding to maximum coefficient 512 gives

```
n = 343,365,276
s = 50
A = -76,160,140,876.
```

The exact checker proves

```
-Rayleigh(H,z) > 866400/1000000 > sqrt(3)/2.
```

The second strict comparison is certified by `4*866400^2 - 3*1000000^2 = 2,595,840,000 > 0`.

Reducing the coefficient scale made `2n` smaller than the NTT modulus, enabling exact recovery of the entire autocorrelation `a(t)=sum_x z(x)z(x+t)` by another NTT. The edge inequality was then rechecked on this newly rounded vector; it was not inherited from the earlier one. All 65537 translations were checked. The largest nonzero absolute overlap is exactly

```
12,426,901 / 343,365,276 < 0.03620.
```

Thus only translation zero reaches 3/5. [extra_transport_check.json](extra_transport_check.json) and its hashed binary witness record the result. This extends round 1's exact finite failure from p=401 to a larger input: a vector can exceed the limiting two-anchor edge while having very small ordinary translation correlations. It still does not provide an infinite family with fixed edge excess, and does not refute an existence claim for some other structured witness. It tells the next inverse-principle prototype which quantifier and finite-size mistakes to avoid.

## Scaling, complexity and limits

For fixed Lanczos width ncv and computed rank r:

- Character construction and one-vector storage are O(p).
- A matvec costs O(p log p); a run with K matvecs costs O(K p log p), plus Krylov orthogonalization.
- Lanczos storage is O(p + m*ncv), not O(m²).
- The six-image symmetry completion uses O(mr) storage and O(mr²) work for fixed group size.
- Seed autocorrelation uses O(p log p) time. Each chosen translation compression costs O(mr²); the fixed eight-shift protocol avoids scanning p dense r-by-r matrices.
- Exact NTT replay costs O(p log p) time and O(p) space per witness. It uses a different integer modulus from the field prime and requires both the supported transform length and the coefficient-recovery bound. Those are checked preconditions, not a universal arbitrary-size backend.

For p=65537, m=16383, the two signs, completion and diagnostics took 58.7 seconds and the process peak RSS was 117 MB on the recorded macOS runtime. A dense H would require about 2.15 GB solely for its entries. The worst recomputed eigenvector residual was 2.25e-9. The exact negative joint witness has directional quotient greater than 0.866423; that number is a lower bound from one vector, not an upper estimate on the edge.

The p~10^6 run uses k=2 per sign and tolerance 1e-6 to keep resources bounded; the smaller run uses k=4 and tolerance 1e-8. Ranks, matvec counts, residuals, wall time and peak memory are recorded per field. Such differing solver budgets preclude treating the scores as an identically sampled asymptotic sequence. No empirical trend in these few primes supplies an exponent.

The algorithm still has no uniform estimate controlling uncomputed directions, no proof that bad edge sequences force a particular arithmetic signature, no growing-depth moment cancellation, and no exact bridge to the official Proximity Prize. These remain mathematical obligations, not numerical settings.

## Prior art and the limited novelty claim

Primary sources inspected during this round:

- [Kunisky, *Spectral pseudorandomness and the road to improved clique number bounds for Paley graphs*, Sections 3,7,8](https://arxiv.org/html/2303.16475v1). The spectral target, character/Fourier structure and localized numerical experiments are existing work. Section 7 explicitly distinguishes bounds on individual necklaces from cancellation among their sum.
- [Alfke, Potts, Stoll and Volkmer, *NFFT meets Krylov methods*](https://arxiv.org/abs/1808.04580). Fast Fourier matrix products embedded in Lanczos without forming a dense graph matrix are established. Our cyclic finite-field case is simpler than their nonuniform kernel setting.
- [Chiu and Parhi, *Long Polynomial Modular Multiplication using Low-Complexity Number Theoretic Transform*](https://arxiv.org/abs/2306.12519). Exact modular convolution, zero padding and circular folding are established algorithmic ingredients.
- [SciPy eigsh documentation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.linalg.eigsh.html). The tool uses the documented ARPACK implicitly restarted Lanczos wrapper through a LinearOperator. The installed SciPy version is recorded locally; the online manual may describe a newer release.
- [Meurant, *The Lanczos and Conjugate Gradient Algorithms*](https://epubs.siam.org/doi/book/10.1137/1.9780898718140). Ritz approximations, finite-precision effects and freshly evaluated residuals are established numerical analysis, not new theorems here.

The defensible contribution is a new implementation in this workspace linking **one-sided arithmetic witness discovery, explicit symmetry completion, and exact large-scale integer replay**, together with the measured failure modes above. This search does not establish that nobody has built an equivalent tool. Neither FFT acceleration nor the NTT certificate is offered as a novel mathematical principle.

## Reproduce

All commands are run from the repository root. Discovery needs NumPy and SciPy. Exact replay additionally uses clang++ and Python; no API, remote solver or LLM is required.

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 tooling_lab/round2/spectral/fft_transport.py
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 tooling_lab/round2/spectral/fft_transport.py --primes 1000033 --k 2 --tol 1e-6
clang++ -std=c++17 -O3 -Wall -Wextra tooling_lab/round2/spectral/exact_ntt.cpp -o tooling_lab/round2/spectral/exact_ntt
python3 tooling_lab/round2/spectral/verify_exact.py
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 tooling_lab/round2/spectral/completion_audit.py
python3 tooling_lab/round2/spectral/extra_transport_check.py
```

[runtime.json](runtime.json) records the executable and library versions. Per-field result files contain exact witness hashes. The binary witness format is little-endian uint32 p,m followed by m pairs of int32 vertex,coefficient. The C++ reader is built on the recorded little-endian macOS host. Source hashes are recorded with the outputs. The original round-1 artifacts are preserved.

## Exact million-prime extension

[million_transport_check.json](million_transport_check.json) extends the combined Rayleigh/translation replay to p=1,000,033 with m=250,007. A separate rounding to maximum coefficient 128 gives

```
n = 195,367,076
s = 4,910
A = 169,466,354,708.
```

The exact checker proves `Rayleigh(H,z) > 867000/1000000 > sqrt(3)/2`; the rational comparison has squared margin `6,756,000,000 > 0`. Every one of the 1,000,033 translations is checked by exact autocorrelation convolution. The largest nonzero overlap is

```
2,189,980 / 195,367,076 < 0.011210,
```

attained at shift 1. Only the zero shift reaches 3/5. Again, the newly quantized vector's Rayleigh inequality is checked from scratch, and all-transform integer recovery is permitted by the checked norm bound. A dense m-by-m double matrix would require 500,028,000,392 bytes, about 500 GB, before eigensolver overhead. The stored binary witness is about 2 MB.

This result is useful as a **feature rejection at large finite size**: the particular implication “every vector beyond the proposed limiting edge has a sizeable ordinary translation correlation” fails for an explicitly replayable million-prime vector. It does not say that another extremal vector lacks arithmetic structure, nor does it give a persistent fixed excess along infinitely many primes. It does not constitute a Paley counterexample.

The exact NTT backend now emits `autocorrelation_computed`. If false, `max_abs_nonzero_translation_numerator=-1`, `max_translation_shift=0`, and `count_translation_ge_3_5=0` are skipped-computation sentinels. **The zero count does not mean there are no large overlaps.** Both special transport checks require this computation to run and verify the resulting count. General Rayleigh replay remains valid when autocorrelation is skipped.

Run the million-prime transport replay after its positive witness exists:

```sh
python3 tooling_lab/round2/spectral/million_transport_check.py
```

## Independent operator and certificate checks

[scaled_operator_check.py](scaled_operator_check.py) performs direct character-row sums for 32 sampled rows at each of p=65537 and p=1,000,033, without constructing the full dense matrix. It also checks 256 sampled character values per prime by Euler's criterion rather than square enumeration, and checks the bilinear symmetry identity with independent random vectors. At million scale the direct row sums use 8,000,224 character products and agree with the FFT within 9.72e-16. These sampled numerical checks support implementation correctness; they are not interval-arithmetic upper certificates.

A separate agent's standard-library oracle uses packed-integer polynomial multiplication, not NumPy, SciPy or the NTT implementation. It independently recovered the full p=65537 character convolution for the two original witnesses and the 512-coefficient witness, matching all signed quadratic forms. It also independently recovered every autocorrelation of the 512 witness, matching the maximum and the unique threshold crossing. This is independent implementation evidence, not external peer review or a formal proof-system audit. Its artifacts are under the sibling `round2/novelty/` directory.
